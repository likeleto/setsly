# PRD: Workout Tracker v1.1 — учебный mock-вход

## Для кого и какая задача

- **Для кого:** учебная демонстрация на занятии. Два вымышленных пользователя — Анна и Борис.
- **Задача:** показать три способа mock-входа, переключение пользователей и отдельную историю тренировок
  у каждого пользователя, не подключая сервер и внешние сервисы.
- **Важно:** это браузерный прототип. Он показывает продуктовый сценарий, но **не обеспечивает
  защиту данных**. Ограничения зафиксированы ниже.

## Основной пользовательский сценарий

1. Открываешь приложение → если сессии нет, видишь экран входа с предупреждением.
2. Входишь одним из трёх способов: пароль, код или mock-Google.
3. Видишь главную с 4 карточками упражнений и панель текущего пользователя.
4. Нажимаешь на карточку → вводишь подход: повторения, «есть доп. вес?» Да/Нет + вес.
5. Нажимаешь «Добавить подход» → заполняешь следующий.
6. «Сохранить тренировку» → запись сохраняется с `userId` текущего пользователя.
7. Открываешь историю → видишь только свои тренировки.
8. Нажимаешь «Выйти» → возвращаешься на экран входа; тренировки остаются в браузере.
9. Входишь другим пользователем → у него своя пустая история.

## Экраны и элементы

### Экран 0 — Вход (учебный mock)

Всегда содержит предупреждение:

> **Учебный mock-вход. Не используйте настоящие пароли**
>
> Это имитация: проверки выполняются в браузере, данные не защищены.

На экране:
- переключатель «По паролю / По коду»;
- раскрывающаяся подсказка «Демонстрационные аккаунты» с email и паролями;
- кнопка «Войти через Google» с подписью «Имитация. Настоящий Google OAuth не подключён»;
- подпись «Разделение пользователей работает только в этом учебном браузерном прототипе».

**Вход по паролю**
- поля Email и Пароль;
- кнопка «Войти»;
- на время проверки — «Проверка...», поля и кнопка заблокированы;
- ошибки: «Введите email и пароль.» и «Неверный email или пароль.»;
- пароль не сохраняется в `localStorage`/`sessionStorage`.

**Вход по коду**
- шаг 1: email + «Получить код»; на время запроса — «Отправляем код...»;
- шаг 2: поле «Код из 6 цифр», кнопка «Подтвердить», «Получить код повторно», «Изменить email»;
- учебный код показывается прямо на экране с пояснением, что отправка письма имитируется;
- повторное получение генерирует новый код и сбрасывает введённый;
- ошибки: «Введите email.», «Аккаунт с таким email не найден.», «Введите 6 цифр.»,
  «Неверный код. Проверьте цифры или получите новый код.».

**Вход через Google**
- открывается локальный диалог «Имитация выбора аккаунта Google»;
- два демонстрационных аккаунта и кнопка «Отмена»;
- отмена оставляет пользователя гостем;
- выбор выполняет mock-вход без настоящего OAuth.

### Экран 1 — Главная

- Панель пользователя: имя, email, кнопка «Выйти» (на всех внутренних экранах).
- Заголовок + кнопка «История».
- 4 карточки: Подтягивания / Отжимания / Брусья / Приседания.
- Блок «Последняя тренировка» — только записи текущего пользователя.
- Баннер старых записей без владельца: «Найдены старые тренировки без владельца: N».
  Перенос выполняется только после inline-подтверждения; «Оставить как есть» скрывает баннер.

### Экран 2 — Ввод подхода

Структура не изменилась: название упражнения, динамический список подходов,
«Добавить подход» / «Сохранить тренировку» / «Отмена». При сохранении запись получает
`userId` текущего пользователя. Защита от двойного клика сохранена.

### Экран 3 — История

Список тренировок текущего пользователя, аккордеон, удаление. `store` не отдаёт чужие записи
и не удаляет их даже при прямом вызове из консоли.

## Демонстрационные аккаунты

| Имя | Email | Пароль | userId |
|---|---|---|---|
| Анна | `anna@example.test` | `demo-anna-123` | `user-anna` |
| Борис | `boris@example.test` | `demo-boris-456` | `user-boris` |

Все три способа входа в один аккаунт дают один `userId` и одну историю. Способ входа
не создаёт нового пользователя. Email сравнивается без учёта регистра и пробелов.

## Хранение данных

| Ключ | Содержимое |
|---|---|
| `workout-tracker-data` | массив тренировок; у новых есть `userId`, у старых может отсутствовать |
| `workout-tracker-session` | `{ "userId": "user-anna" }` — только идентификатор, без пароля |

Правила:
- старые записи без `userId` не удаляются автоматически и не показываются ни одному пользователю;
- перенос старых записей — явное одноразовое действие с подтверждением;
- после переноса владелец сохраняется, и запись больше не может быть присвоена другому;
- `results`, `approaches`, `reps`, `hasExtraWeight`, `extraWeightKg`, `date`, `time`, `id`
  при переносе не меняются;
- битый JSON трактуется как пустой список.

Подробная модель — сущности, поля, связи, обязательность и операции — в `data-model.md`.

### Ограничение безопасности

> **Разделение пользователей работает только внутри учебного браузерного прототипа.**
> `localStorage` и клиентские проверки **не защищают данные** от человека с доступом к браузеру,
> DevTools или файлам профиля. Пароли демо-аккаунтов лежат в исходниках, код входа показывается
> на экране. Для продакшена нужны сервер, хеширование паролей, HttpOnly-сессии и серверная
> авторизация каждого запроса; `userId`, переданный клиентом, нельзя считать доверенным.

## Технические решения

- **Vite 7 + React 19 + TypeScript 5.9** (strict)
- **React Router 7** — маршруты `/`, `/workout/:exerciseKey`, `/history`
- **Tailwind CSS 4 + shadcn/ui** (`base-nova` на `@base-ui/react`)
- **Auth-слой:** `src/auth/demoUsers.ts` + `src/auth/AuthContext.tsx`
  (`signInWithPassword`, `requestCode`, `verifyCode`, `signInWithGoogle`, `signOut`)
- **Store:** `src/store/index.ts`; владелец проверяется в store, а не только в UI
- **Сессия:** отдельный ключ, восстанавливается при загрузке приложения
- **Задержка проверки:** около 450 мс для демонстрации состояний «проверка»
- **Линтера и тестов нет**; проверки — `npm run build` и ручные/автоматизированные сценарии

## Проверки результата

Базовые:
1. **Сохранение:** после ввода 2–3 подходов тренировка появляется в истории с датой и всеми данными.
2. **Responsive:** на 375px карточки и формы читаются, кнопки нажимаются, горизонтального скролла нет.
3. **Персистентность:** после F5 данные и сессия сохраняются.

Вход и изоляция:
4. Каждый из трёх способов позволяет войти.
5. Неверный пароль и неверный код показывают ошибку.
6. Отмена Google оставляет пользователя гостем.
7. Вход разными способами в один аккаунт открывает одну историю.
8. Пользователь A создаёт тренировку; B её не видит и не может удалить через store.
9. Возврат в A восстанавливает его историю.
10. F5 сохраняет сессию и тренировки; выход сохраняет тренировки.
11. Перенос старых записей выполняется только после подтверждения и только одному пользователю.

Фактический прогон 2026-11-12: `npm run build` проходит; store-проверки владения/сессии/legacy
и UI-сценарии в headless Chrome (три входа, ошибки, отмена Google, изоляция A/B, F5, выход,
перенос legacy, 375px) пройдены.
